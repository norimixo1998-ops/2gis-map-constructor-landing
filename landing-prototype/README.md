# Прототип библиотеки лендингов Dev2GIS

Реализованные секции, их постоянные ID `S01`–`S14`, назначение и ограничения перечислены в [каталоге](../specs/landing-blocks-spec.md). ID обозначает **тип**, а не позицию. Для нового лендинга порядок берётся из ТЗ маркетинга: каждый смысловой блок ТЗ сопоставляется с типом и вариантом компонента, после чего в маршрут передаются реальные тексты, ссылки и визуалы. Заголовки H1/H2 остаются контентом страницы и могут отличаться от имени типа.

## Текущие маршруты

| Маршрут | Порядок секций из кода | Данные |
| --- | --- | --- |
| `/` — Конструктор карт | S01 (вариант 2) → S02 → S04 → S11 → S08 → S09 → S10 → S12 → S13 | Данные содержательных секций, включая S10, находятся в [`content/map-constructor.ts`](content/map-constructor.ts). |
| `/geoflow-holiday` — черновик акции | S01 (вариант 1) → S07 → S02 → S08 → S09 → S11 → S12 | [`content/geoflow-holiday.ts`](content/geoflow-holiday.ts); состав описан в [паспорте сборки](../specs/geoflow-holiday-blocks-spec.md). |
| `/geoflow-hero-preview` — новая сборка акции | S01 → S03 → S09 → S14 → S05 → S04 → S12 → дополнительная форма | [`content/geoflow-hero-preview.ts`](content/geoflow-hero-preview.ts); отдельный упрощённый Header, Hero, горизонтальные тезисы, четыре шага, горизонтальная панель сценариев, блок инструментов с показателями, карточки с изображениями, пять временных вопросов FAQ и короткая форма после них. |

Порядок задают соответственно [`app/page.tsx`](app/page.tsx) и [`app/geoflow-holiday/page.tsx`](app/geoflow-holiday/page.tsx). На акции CTA с саморегистрацией стоит **перед** FAQ, как предусмотрено её сценарием. Адрес саморегистрации не подтверждён, поэтому кнопка отключена.

На `/` в первом экране подключено готовое изображение карты. Отдельные предпросмотры: `/hero-variant-2-preview`, `/main-values-preview`, `/image-feature-cards-preview`, `/icon-feature-numbers-preview`, `/icon-feature-cards-preview`, `/start-work-preview`, `/faq-preview`, `/header-preview`. Самостоятельный S05 используется на новой странице акции; S06 сохраняет обычный предпросмотр.

`/optional-cta-form-preview` показывает [дополнительный CTA с короткой формой](../specs/optional-cta-form-spec.md) на основе полей S13. Это необязательный вариант, он не включён в канонический каталог; в новой локальной сборке акции он размещён после FAQ.

Общие Header и Footer подключаются через [`app/layout.tsx`](app/layout.tsx). ИИ-чат подключён только на `/`; он пока показывает демонстрационный ответ и не связан с моделью. Форма заявки S13 без `action` тоже работает лишь как предпросмотр и не отправляет данные в CRM.

## Новый лендинг

1. Составить карту соответствия: блок ТЗ → ID секции → вариант компонента → контент и визуалы. Сохранить порядок ТЗ; недостающие данные отметить, не заменяя их содержанием другой страницы.
2. Создать `content/<slug>.ts`, положить изображения в `public/images/<slug>/` и добавить маршрут `app/<slug>/page.tsx`. Использовать готовые компоненты из `components/` и общий `layout.tsx`.
3. Проверить страницу на ширинах 375, 768, 1024 и 1440 px, действия кнопок, переносы, визуалы и отсутствие горизонтальной прокрутки. Расстояние H2 → описание (20 px) и от описания или H2 до следующего блока (36/48 px) проверяется командой `node check-section-heading-gaps.mjs`, иерархия H1/H2 на 390 и 1440 px — командой `node check-heading-type-scale.mjs` при работающем `pnpm dev`; остальные `check-*.mjs` описаны в паспортах блоков.

Для локального запуска из `landing-prototype`: `pnpm install`, затем `pnpm dev`. Открыть <http://127.0.0.1:3000/>. Production-сборка: `pnpm build`.
