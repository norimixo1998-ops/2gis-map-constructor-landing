# Прототип библиотеки лендингов Dev2GIS

Реализованные секции, их постоянные ID `S01`–`S10`, назначение и ограничения перечислены в [каталоге](../specs/landing-blocks-spec.md). ID обозначает **тип**, а не позицию. Для нового лендинга порядок берётся из ТЗ маркетинга: каждый смысловой блок ТЗ сопоставляется с типом и вариантом компонента, после чего в маршрут передаются реальные тексты, ссылки и визуалы. Заголовки H1/H2 остаются контентом страницы и могут отличаться от имени типа.

## Текущие маршруты

| Маршрут | Порядок секций из кода | Данные |
| --- | --- | --- |
| `/` — Конструктор карт | S01 (вариант 2) → S02 → S03 → S08 → S05 → S06 → S07 → S09 → S10 | [`content/map-constructor.ts`](content/map-constructor.ts); S07 пока использует данные из [`content/geoflow-logistics-preview.ts`](content/geoflow-logistics-preview.ts). |
| `/geoflow-holiday` — черновик акции | S01 (вариант 1) → S04 → S02 → S05 → S06 → S08 → S09 | [`content/geoflow-holiday.ts`](content/geoflow-holiday.ts); состав описан в [паспорте сборки](../specs/geoflow-holiday-blocks-spec.md). |

Порядок задают соответственно [`app/page.tsx`](app/page.tsx) и [`app/geoflow-holiday/page.tsx`](app/geoflow-holiday/page.tsx). На акции CTA с саморегистрацией стоит **перед** FAQ, как предусмотрено её сценарием. Адрес саморегистрации не подтверждён, поэтому кнопка отключена.

На `/` в первом экране подключено готовое изображение карты. Отдельные предпросмотры: `/hero-variant-2-preview`, `/main-values-preview`, `/solved-tasks-preview`, `/start-work-preview`, `/faq-preview`, `/header-preview`.

Общие Header и Footer подключаются через [`app/layout.tsx`](app/layout.tsx). ИИ-чат подключён только на `/`; он пока показывает демонстрационный ответ и не связан с моделью. Форма заявки S10 без `action` тоже работает лишь как предпросмотр и не отправляет данные в CRM.

## Новый лендинг

1. Составить карту соответствия: блок ТЗ → ID секции → вариант компонента → контент и визуалы. Сохранить порядок ТЗ; недостающие данные отметить, не заменяя их содержанием другой страницы.
2. Создать `content/<slug>.ts`, положить изображения в `public/images/<slug>/` и добавить маршрут `app/<slug>/page.tsx`. Использовать готовые компоненты из `components/` и общий `layout.tsx`.
3. Проверить страницу на ширинах 375, 768, 1024 и 1440 px, действия кнопок, переносы, визуалы и отсутствие горизонтальной прокрутки. Подробности каждого типа и существующие `check-*.mjs` находятся в его паспорте.

Для локального запуска из `landing-prototype`: `pnpm install`, затем `pnpm dev`. Открыть <http://127.0.0.1:3000/>. Production-сборка: `pnpm build`.
