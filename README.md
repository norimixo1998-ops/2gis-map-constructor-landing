# Библиотека секций Dev2GIS и прототипы лендингов

В [`landing-prototype/`](landing-prototype/) находятся адаптивные страницы и переиспользуемые компоненты, а в [`specs/`](specs/) — их паспорта и правила сборки. Сейчас есть два лендинга: Конструктор карт на `/` и черновик акции ГеоПотока на `/geoflow-holiday`. Контент каждой страницы хранится отдельно в `landing-prototype/content/`.

Библиотека содержит **11 типов содержательных секций S01–S11**. ID обозначает тип, а не место на странице. Для нового лендинга агент сопоставляет каждый блок ТЗ маркетинга с типом и вариантом секции, затем собирает их **в порядке ТЗ** с реальным контентом. Первый экран и основное действие нужны на каждом лендинге; остальные секции выбираются по содержанию ТЗ. Подробные условия включения, варианты и правила сборки — в [каталоге секций](specs/landing-blocks-spec.md).

## Секции библиотеки

Названия ниже совпадают с заголовками паспортов. Английские имена в колонке компонентов — технические идентификаторы в коде; они не задают видимый заголовок секции на странице.

| ID | Название и паспорт | Зачем нужен и когда подходит | Компонент в коде |
| --- | --- | --- | --- |
| S01 | [Первый экран](specs/hero-variant-1-spec.md) · [вариант 2](specs/hero-variant-2-spec.md) | Сразу объясняет, что это за продукт, кому он полезен и какое действие предлагается. Нужен на каждом лендинге; выбирают один вариант оформления. | `Hero` / `HeroVariant2` |
| S02 | [Ключевые тезисы](specs/main-values-spec.md) | Помогает быстро просмотреть несколько главных выгод, возможностей или условий. Подходит, когда их можно выразить короткими самостоятельными утверждениями. | `MainValues` |
| S03 | [Возможности в карточках (с изображениями)](specs/image-feature-cards-spec.md) | Показывает возможности продукта в отдельных карточках с подготовленными изображениями: картами, интерфейсами или коллажами. Выбирайте, когда для каждой возможности есть смысловой визуал. | `ImageFeatureCards` |
| S04 | [Возможности в карточках (с иконками)](specs/icon-feature-cards-spec.md) | Показывает возможности через заголовок, короткое описание и иконку без отдельных изображений. Подходит, когда есть иконки, но нет подготовленных визуалов. Акцентная CTA-карточка добавляется только по ТЗ, с одной или двумя кнопками. | `IconFeatureCards` |
| S05 | [Сферы применения](specs/audience-scenarios-spec.md) | Показывает, для каких аудиторий или отраслей подходит продукт. Используется, если в ТЗ перечислены разные группы пользователей или сценарии применения. | `AudienceScenarios` |
| S06 | [Техническая демонстрация](specs/technical-demonstration-spec.md) | Показывает интерфейс, результат работы или техническую возможность в крупном визуале с пояснением. Подходит, когда одних тезисов и карточек недостаточно. | `TechnicalDemonstration` |
| S07 | [Шаги запуска](specs/start-work-spec.md) | Показывает последовательность подключения и первых действий. Подходит, если посетителю важно понять, как начать пользоваться продуктом. | `StartWork` |
| S08 | [Причины выбрать 2ГИС](specs/reasons-spec.md) | Добавляет аргументы в пользу платформы и помогает снять сомнения. Используется, когда в ТЗ есть отдельные подтверждённые причины выбора. | `Reasons` |
| S09 | [CTA с кнопкой](specs/intermediate-cta-spec.md) | Предлагает перейти к следующему действию: регистрации, форме или другой странице. Подходит для дополнительного призыва либо основного действия без формы. | `IntermediateCta` |
| S10 | [Вопросы и ответы](specs/faq-spec.md) | Закрывает частые вопросы об использовании продукта и условиях. Добавляется только при наличии утверждённых вопросов и ответов. | `Faq` |
| S11 | [Форма заявки](specs/cta-form-spec.md) | Собирает контактные данные и контекст обращения. Подходит, когда основной сценарий страницы — отправка заявки. | `LeadForm` |

Если в ТЗ даны короткие выгоды, начните с S02; для отдельных возможностей с подготовленными изображениями выбирайте S03, с иконками и текстом — S04. Для подробного визуального объяснения продукта используйте «Техническую демонстрацию». Для следующего действия без формы подойдёт CTA с кнопкой, для заявки — форма. Это ориентиры для выбора типа, а не заданный порядок секций.

[Header](specs/header-spec.md) и [Footer](specs/footer-spec.md) составляют общую оболочку страницы; [ИИ-чат](specs/ai-chat-handoff.md) — вспомогательный виджет. Они не входят в 11 содержательных секций. S09 и S11 — варианты конверсионного действия: конкретный блок и его место задаёт ТЗ.

| Страница | Фактический порядок секций |
| --- | --- |
| `/` — Конструктор карт | S01 → S02 → S03 → S09 → S06 → S07 → S08 → S10 → S11 |
| `/geoflow-holiday` — акция ГеоПотока | S01 → S05 → S02 → S06 → S07 → S09 → S10 |

На `/` используется S01, вариант 2, с подготовленным изображением карты. Подробности маршрутов — в [README приложения](landing-prototype/README.md).

## Как собирается лендинг

1. Размечаем каждый смысловой блок ТЗ типом S01–S11 и вариантом компонента, сохраняя порядок ТЗ. Выбираем один первый экран и согласованное основное действие. Неизвестный тип блока сначала описываем и согласуем.
2. Для каждого блока берём готовый компонент из `components/`. Если макет требует нового варианта, фиксируем правило в `specs/` и обновляем компонент.
3. Тексты, ссылки и пути к изображениям храним отдельно в `content/`.
4. Страница в `app/` воспроизводит порядок ТЗ и передаёт блокам данные. Для следующего лендинга используем `content/<slug>.ts`, `public/images/<slug>/` и отдельный маршрут `app/<slug>/page.tsx`, сохранив общий `layout.tsx`.
5. Проверяем страницу на широком и мобильном экранах, затем передаём ссылку маркетингу на ревью.

## Публикация

При отправке изменений в ветку `main` workflow `.github/workflows/pages.yml` собирает статическую версию для GitHub Pages. В настройках репозитория нужно выбрать **Settings → Pages → Build and deployment → Source: GitHub Actions**. Публичный адрес: `https://norimixo1998-ops.github.io/2gis-map-constructor-landing/`. Путь `/2gis-map-constructor-landing` задаётся при сборке и применяется к изображениям, иконкам, шрифтам и файлам приложения. Локальная разработка остаётся доступной по корневому пути `/`.

Форма заявки на опубликованном ревью-лендинге работает в режиме предпросмотра: отправка в CRM пока не подключена.
