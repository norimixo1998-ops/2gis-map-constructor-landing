# Конструктор карт 2ГИС — лендинг и библиотека блоков

В `landing-prototype/` находится готовый адаптивный лендинг Конструктора карт 2ГИС. В `specs/` описаны правила его блоков. Тексты и изображения конкретного лендинга подключены через `landing-prototype/content/map-constructor.ts`.

## Структура

| Путь | Назначение |
| --- | --- |
| [`specs/landing-blocks-spec.md`](specs/landing-blocks-spec.md) | Каталог секций B01–B07, их назначение, варианты и общие правила сборки. |
| [`specs/`](specs/) | Подробные паспорта Header, Footer и CTA-формы. Новые паспорта добавляются сюда, когда краткого описания в каталоге недостаточно. |
| [`landing-prototype/`](landing-prototype/) | Next.js приложение: работающий каркас, где блоки проверяются вместе. |
| [`landing-prototype/components/`](landing-prototype/components/) | Переиспользуемые блоки: Hero, Header, Footer и форма заявки. Разметка (`.tsx`) и стили (`.module.css`) лежат рядом. |
| [`landing-prototype/content/`](landing-prototype/content/) | Данные конкретного предпросмотра: тексты, действия и пути к визуалам. |
| [`landing-prototype/app/`](landing-prototype/app/) | Маршруты и сборка страницы. `layout.tsx` добавляет общие Header и Footer; `page.tsx` определяет порядок секций. |
| [`landing-prototype/public/`](landing-prototype/public/) | Изображения, логотип и иконки, на которые ссылаются компоненты или данные страницы. Локальные шрифты пока лежат в `app/Fonts/`. |

Проверки находятся в `landing-prototype/check-*.mjs`, их снимки — в `landing-prototype/preview-checks/`. Инструкция по запуску — в [README приложения](landing-prototype/README.md).

## Как собирается лендинг

1. Сопоставляем ТЗ с блоками из каталога. Неизвестный тип блока сначала описываем и согласуем.
2. Для каждого блока берём готовый компонент из `components/`. Если макет требует нового варианта, фиксируем правило в `specs/` и обновляем компонент.
3. Тексты, ссылки и пути к изображениям храним отдельно в `content/`.
4. Страница в `app/` задаёт порядок блоков и передаёт им данные. Для следующего лендинга используем `content/<slug>.ts`, `public/images/<slug>/` и отдельный маршрут `app/<slug>/page.tsx`, сохранив общий `layout.tsx`.
5. Проверяем страницу на широком и мобильном экранах, затем передаём ссылку маркетингу на ревью.

## Публикация

При отправке изменений в ветку `main` workflow `.github/workflows/pages.yml` собирает статическую версию для GitHub Pages. В настройках репозитория нужно выбрать **Settings → Pages → Build and deployment → Source: GitHub Actions**. Публичный адрес: `https://norimixo1998-ops.github.io/2gis-map-constructor-landing/`. Путь `/2gis-map-constructor-landing` задаётся при сборке и применяется к изображениям, иконкам, шрифтам и файлам приложения. Локальная разработка остаётся доступной по корневому пути `/`.

Форма заявки на опубликованном ревью-лендинге работает в режиме предпросмотра: отправка в CRM пока не подключена.
