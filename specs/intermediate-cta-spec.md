# Промежуточный CTA

## Назначение и место

Короткий призыв к действию между содержательными секциями лендинга. Блок необязателен: его добавляют по ТЗ там, где посетителю нужен следующий шаг до финальной формы заявки. В текущем предпросмотре он расположен после демонстрации продукта и перед блоком причин.

Источник композиции — фреймы `intermediate CTA_desktop` и `intermediate CTA_mobile` в [файле конструктора Figma](https://www.figma.com/design/2GackEUWd1sfbXBU0OUElS/Конструктор). На десктопе широкая зелёная карточка содержит обязательный заголовок, необязательное описание и одну или две кнопки слева, а отдельную иллюстрацию справа. На мобильном порядок: заголовок, описание при его наличии, иллюстрация, одна широкая кнопка.

## Варианты по ТЗ

| Поле | Правило |
| --- | --- |
| Заголовок | Обязателен. Блок может состоять из заголовка, иллюстрации и одной кнопки. |
| Описание | Добавляется только если оно предусмотрено в ТЗ. Если описания нет, текстовый абзац и отступ под ним не создаются. |
| Основная кнопка | Обязательна, белая. Если в ТЗ одно действие, показывается только она. |
| Вторая кнопка | Добавляется только если в ТЗ есть второе действие. На десктопе она полупрозрачная; на мобильном по текущему макету скрыта, поэтому мобильным действием всегда должна быть основная кнопка. |

Отсутствующие описание и вторую кнопку не заменять типовым текстом или ссылкой из другого лендинга. Текст, количество действий и адреса кнопок определяются ТЗ конкретной страницы.

## Контракт компонента

Реализация — `landing-prototype/components/intermediate-cta/IntermediateCta.tsx` и CSS Module рядом. Данные страницы — `landing-prototype/content/geoflow-logistics-preview.ts`; место блока задаёт `landing-prototype/app/page.tsx`.

- `id?: string` — якорь, по умолчанию `intermediate-cta`.
- `title: string` — заголовок из ТЗ. Строки переносятся естественно; ручной перенос не обязателен.
- `description?: string` — короткое пояснение. Если его нет в ТЗ, свойство опускается: компонент не выводит абзац.
- `primaryAction: { label; href; mobileLabel?; target? }` — обязательная белая кнопка. Мобильная подпись при необходимости отличается от десктопной.
- `secondaryAction?` — необязательная вторая кнопка на десктопе. Если в ТЗ одно действие, свойство опускается; по текущему макету вторая кнопка скрыта на мобильном.
- `image?: { desktop; mobile?; alt }` — отдельные PNG иллюстрации. Если файла пока нет, отображается плейсхолдер черновика. Для декоративной иллюстрации допустим пустой `alt`, для смысловой нужен краткий текст. В текущем предпросмотре обе версии PNG подключены.

Примеры данных для сборки из ТЗ:

```ts
// Только заголовок и одна белая кнопка
{ title: "Заголовок", primaryAction: { label: "Начать", href: "#lead-form" }, image }

// С описанием и двумя кнопками на десктопе
{ title: "Заголовок", description: "Описание", primaryAction: { label: "Начать", href: "#lead-form" }, secondaryAction: { label: "Подробнее", href: "/details" }, image }
```

В текущем предпросмотре подписи и описание — макетные, обе ссылки ведут к `#lead-form`; для нового лендинга их нужно заменить утверждённым содержанием и целевыми URL.

## Геометрия и рост текста

Карточка на широком экране ограничена шириной `1168 px`, имеет минимальную высоту `280 px`, радиус `28 px`, внутренние поля `48 px` по горизонтали. Заголовок — `44/52 px`, описание — `16/24 px`, кнопки высотой не меньше `56 px`. Левая текстовая область ограничена шириной `680 px` и не заходит в область иллюстрации. Правая область иллюстрации занимает `38%` карточки и растягивается на **фактическую высоту** карточки. Когда текст становится длиннее и карточка растёт, высота области изображения растёт вместе с ней; PNG заполняет её через `object-fit: cover`, излишек по краям кадрируется.

До `899 px` карточка становится вертикальной: боковые поля `24 px`, радиус `20 px`, заголовок `30/38 px`, иллюстрация между описанием и кнопкой. Иллюстрация сохраняет собственные пропорции PNG без заданного в CSS соотношения сторон, ограничена шириной `440 px` и помещается целиком через `object-fit: contain`; минимальная высота области — `218 px`. Основная кнопка занимает всю доступную ширину, второе действие не показывается. При длинном тексте карточка растёт в потоке страницы, не перекрывая иллюстрацию и кнопку. На ширине `700–899 px` вертикальная композиция сохраняется, а межсекционный отступ остаётся десктопным. На ширине до `699 px` отступ до соседних секций — `64 px`; на широких и промежуточных экранах — `120 px`.

## Ассеты

Папка для файлов: `landing-prototype/public/images/intermediate-cta/`. Текущие имена: `desktop_image.png`, `mobile_image.png`; пути в данных: `/images/intermediate-cta/desktop_image.png` и `/images/intermediate-cta/mobile_image.png`. В PNG только иллюстрация с прозрачностью, без зелёной карточки, текста и кнопок. При замене файлов сохранить имена или обновить объект `image` в данных страницы.

## Проверка

`node check-intermediate-cta.mjs` при работающем `pnpm dev` проверяет ширины `375`, `768`, `1440 px`, загрузку нужной версии PNG, межсекционные интервалы, порядок мобильных элементов, количество видимых кнопок, отсутствие горизонтального переполнения и рост карточки при длинном заголовке и описании. Снимки сохраняются в `landing-prototype/preview-checks/`.
